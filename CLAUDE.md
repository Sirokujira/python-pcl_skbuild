# python-pcl_skbuild — Claude Code guide

PCL Python bindings: scikit-build + CMake + Cython, with `.pxd` declarations
auto-generated by [cppast2autopxd](https://github.com/sirokujira/cppast2autopxd).
The full pipeline, generated-file policy, and environment rules are in
`.claude/rules/pipeline.md` (auto-loaded) — read them before editing.

## Commands

```sh
# regen pxd (requires: pip install git+https://github.com/sirokujira/cppast2autopxd)
python pxdgen/generate.py
python pxdgen/generate.py --check      # verify committed pxd not stale

# tests that run WITHOUT PCL installed (always run these)
pytest tests/test_pxd_pipeline.py -v

# full build + runtime tests (needs a PCL install)
pip install -v .
pytest tests/test_pointcloud.py -v
```

Slash commands: `/generate-pxd` (regen + verify), `/build-ext` (native
build + runtime tests).

## About .pyd / .so binary modules

- The build output `_pointcloud.so` / `_pointcloud.pyd` is produced by
  scikit-build (CMake `python_extension_module`) — NEVER commit binaries;
  `.gitignore` already excludes them.
- `ModuleNotFoundError: pcl._pointcloud` means the extension is not built
  for the current interpreter — build with `pip install .`, don't "fix"
  the import.
- Windows builds produce `.pyd` via MSVC (see `setup.py` CMAKE_ARGS);
  Linux/macOS produce `.so`. Same source, no per-platform code.

## Adding PCL API

1. Extend a mirror header in `pxdgen/headers/pcl/` + the `[[headers]]`
   entry in `pxdgen/pcl_headers.toml`.
2. `python pxdgen/generate.py` (never hand-edit `src/pcl/pxd/` — the
   settings deny it).
3. Write/extend a `.pyx`, register the module in `src/pcl/CMakeLists.txt`
   (add_cython_target + add_library + python_extension_module + install).
4. Add tests for both layers; `pytest tests/test_pxd_pipeline.py` must
   pass. If generator output looks wrong, fix cppast2autopxd (it has its
   own tests), not the generated files here.
