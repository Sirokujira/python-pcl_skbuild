# python-pcl_skbuild — Claude Code guide

PCL Python bindings: scikit-build + CMake + Cython, with `.pxd` declarations
auto-generated by [cppast2autopxd](https://github.com/sirokujira/cppast2autopxd).
The full pipeline, generated-file policy, PCL version policy, and
environment rules are in `.claude/rules/pipeline.md` (auto-loaded) — read
them before editing.

**Requires PCL 1.11 or newer** (enforced at CMake configure time).

## Commands

```sh
# regen pxd (requires: pip install git+https://github.com/sirokujira/cppast2autopxd)
python pxdgen/generate.py
python pxdgen/generate.py --check      # verify committed pxd not stale

# tests that run WITHOUT PCL installed (always run these)
pytest tests/test_pxd_pipeline.py -v

# full build + runtime tests (needs a PCL install)
pip install -v .
pytest tests/ -v

# binding overhead vs native C++ (needs PCL + the built extension)
sh bench/run.sh 1000000 7
```

Slash commands: `/generate-pxd` (regen + verify), `/build-ext` (native
build + runtime tests).

## Layout

```
pxdgen/headers/pcl/**/*.h   mirror headers, mirroring PCL's own tree
pxdgen/pcl_headers.toml     [generator] + substitutions + root headers
pxdgen/modules/*.toml       [[headers]] entries per PCL module, nothing else
src/pcl/pxd/**/*.pxd        GENERATED (one subpackage per PCL module)
src/pcl/*.pyx               hand-written wrappers, one extension module each
src/pcl/_pointcloud.pxd     hand-written; exports PointCloud to the others
src/pcl/compat/*.h          C++ shims for what Cython cannot state
```

## About .pyd / .so binary modules

- Build output (`_pointcloud`, `_filters`, `_kdtree`, `_segmentation`) is
  produced by scikit-build (CMake `python_extension_module`) — NEVER
  commit binaries; `.gitignore` already excludes them.
- `ModuleNotFoundError: pcl._pointcloud` means the extension is not built
  for the current interpreter — build with `pip install .`, don't "fix"
  the import.
- Windows builds produce `.pyd` via MSVC (see `setup.py` CMAKE_ARGS);
  Linux/macOS produce `.so`. Same source, no per-platform code.

## Adding PCL API

1. Extend or add a mirror header under `pxdgen/headers/pcl/`, mirroring
   PCL's directory layout.
2. Add the `[[headers]]` entry to the matching `pxdgen/modules/<group>.toml`
   (create the file for a new PCL module; `[[headers]]` entries only).
3. `python pxdgen/generate.py` (never hand-edit `src/pcl/pxd/` — the
   settings deny it). New pxd directory? Add `__init__.py` **and**
   `__init__.pxd`.
4. Write/extend a `.pyx` and append the module name to the list in
   `src/pcl/CMakeLists.txt`. Add the PCL component to
   `find_package(PCL ... COMPONENTS ...)` if it is a new one.
5. Add tests for both layers; `pytest tests/` must pass. If generator
   output looks wrong, fix cppast2autopxd (it has its own tests), not the
   generated files here.

`cppast2autopxd <header> --scaffold` writes a starting-point `.pyx` (owned
pointer, ctor/dtor, primitive-only methods forwarded, the rest as TODO
comments). It never overwrites an existing file.
