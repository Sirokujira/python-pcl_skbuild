# python-pcl_skbuild — Claude Code guide

PCL Python bindings: scikit-build + CMake + Cython, with `.pxd` declarations
auto-generated by [cppast2autopxd](https://github.com/sirokujira/cppast2autopxd).

## Pipeline (memorize this)

```
pxdgen/headers/pcl/*.h   mirror headers (self-contained PCL API stand-ins)
   -> cppast2autopxd     config: pxdgen/pcl_headers.toml
src/pcl/pxd/*.pxd        GENERATED, committed; `cdef extern from "pcl/..."`
   -> cimport
src/pcl/_pointcloud.pyx  hand-written wrapper classes
   -> cython --cplus     (CMake: add_cython_target in src/pcl/CMakeLists.txt)
   -> C++ compile with REAL PCL headers
_pointcloud.so (.pyd on Windows)   the binary extension module
```

- `src/pcl/pxd/*.pxd` are **generated files**: never hand-edit them. Change
  the mirror headers and/or `pxdgen/pcl_headers.toml`, then run
  `python pxdgen/generate.py`.
- Mirror headers only need names/types to match the real PCL API; the real
  layout/implementation comes from the actual PCL headers at C++ compile
  time (`extern_from` points at `pcl/...` real paths).

## Commands

```sh
# regen pxd (requires: pip install git+https://github.com/sirokujira/cppast2autopxd)
python pxdgen/generate.py
python pxdgen/generate.py --check      # verify committed pxd not stale

# tests that run WITHOUT PCL installed (always run these)
pytest tests/test_pxd_pipeline.py -v

# full build + runtime tests (needs libpcl-dev)
pip install -v .
pytest tests/test_pointcloud.py -v
```

## Build troubleshooting

- `pip install .` failing in `FindCython.cmake` / CMake configure after a
  previous successful build: the `_skbuild/` cache references a deleted pip
  build env — run `rm -rf _skbuild` and rebuild.
- CMake can't find PCL: install `libpcl-dev` or set `PCL_ROOT`.

## About .pyd / .so binary modules

- The build output `_pointcloud.so` / `_pointcloud.pyd` is produced by
  scikit-build (CMake `python_extension_module`) — NEVER commit binaries;
  `.gitignore` already excludes `*.so`/`*.pyd`.
- Import errors like `ModuleNotFoundError: pcl._pointcloud` mean the
  extension is not built for the current interpreter — build with
  `pip install .` (needs PCL), don't "fix" the import.
- Windows builds produce `.pyd` via MSVC (`cl.exe`, see `setup.py`
  CMAKE_ARGS); Linux/macOS produce `.so`. Same source, no per-platform code.

## Editing rules

1. New PCL API to wrap? Extend `pxdgen/headers/pcl/`, update
   `pxdgen/pcl_headers.toml`, regenerate, then write/extend a `.pyx`, add the
   module to `src/pcl/CMakeLists.txt` (add_cython_target + add_library +
   python_extension_module + install), and add tests for both layers.
2. After ANY change to mirror headers or generator config,
   `pytest tests/test_pxd_pipeline.py` must pass — it fails if committed pxd
   files are stale or the wrapper no longer transpiles.
3. If cppast2autopxd output looks wrong, fix it THERE (it has its own tests),
   not by hand-editing generated pxd here.
4. Runtime tests (`tests/test_pointcloud.py`) auto-skip when the extension
   isn't built; that's expected on machines without PCL.
